# 0.9.0 — additive discovery and changed-title version families

Topic discovery now preserves original queries and quotas before adding source-native complementary routes. The default additional budget is 50 provider result slots per supported source; it is not taken out of the original budget. Plans and route origins remain auditable. Explicit original-only mode and fixed-budget strategy experiments remain available. Unsupported or restricted queries are preserved with planning diagnostics, not silently broadened. Reusing a generated plan does not append the same queries again. Frozen-list resume does not rerun discovery.

Version-family metadata matching no longer requires an identical title for every preprint/journal pair. Changed-title candidates need corroborating author, chronology, role, distinctive abstract and contextual result evidence. Observed study/result conflicts block grouping; absent evidence is not confirmed agreement. These remain high-confidence **provisional metadata groups**, separate from provider-confirmed relationships. Every original record, identifier, screening decision and file identity remains available. Grouping never permits a different version's PDF to pass article-identity verification.

Compatibility: no new dependency, paid source, institutional session, browser plugin automation or Zotero write. Existing manifests, source artifacts and reading receipts remain immutable. Extraction and AI reading retain their separate definitions. Report bounded candidate yield, relevance, version-family counts and identity-verified detailed-body availability separately; neither tests nor more hits establish exhaustive recall or independent study counts.

Provider semantics are documented in the [PubMed User Guide](https://pubmed.ncbi.nlm.nih.gov/help/) and [Europe PMC search help](https://europepmc.org/help). PubMed unfielded mapping and Europe PMC unfielded search are complementary routes, not equivalent search languages. Source-specific query translations and actual result caps remain the evidence for each run.
