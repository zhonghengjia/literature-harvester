# Manifest schema and retrieval metrics

The manifest is the source of truth for a frozen run. New runs use schema_version 2; the loader also accepts schema 1. Research-mode sidecars have independent schemas defined in research-reading.md; their existence does not redefine the PDF population or metrics below.

## Population and provenance

- run_id, query, created_at, updated_at identify a run.
- settings holds non-secret source choices, selected/pre-filter candidate caps, explicit filters, PDF target and output folder. On resume, enabled_sources reflects the current configuration used for retrieval; the frozen discovery history remains in source_status and the unchanged parent manifest. Resume never repeats discovery.
- source_status retains source errors, partial-page counts, continuation hints and content blocked/disabled states. A continuation hint is diagnostic; resume does not repeat discovery.
- records contains the entire selected pool: successes, failures, deferred and pending records. New runs never move failures out of this array.
- A schema 1 download_attempts array is merged into the population without dropping conflicting identifiers; duplicate legacy outcomes are retained as record history. Resuming creates a fresh schema 2 run, parent_run_id and parent_manifest_sha256, leaving the source manifest unchanged.
- attempts records candidate/actual request URLs, source, stage, outcome, errors and deadlines. Resolver warnings and per-record fallback_sources remain available in candidate metadata/extra.
- host_retry_at persists server deadlines across clients and resumed runs. When a future record retry_at is attributable to a host, it does not block eligible alternatives on other hosts; the transport still enforces the full original deadline. An unattributable legacy record deadline remains conservatively deferred. fallback_source_status aggregates records considered and provider outcomes.
- metrics is generated by outcomes.summarize_outcomes, the same definition used by CLI, coverage and reports.
- Optional research_context pins the normalized query plan and complete discovery inventory by file path and SHA-256, with selected_candidate_ids describing this run's queue. The loader verifies these sidecars before reuse; resume retains their original immutable references. The complete inventory does not enter collect_population. A screening operation creates a new explicitly included population and ledger, never edits its parent run; its manifest can be used for content or separately requested PDF resume.

## Identity and files

Identifiers are normalized DOI, PMID, PMCID and arXiv values; null-like strings are empty, not shared keys. Conflicting strong identifiers are retained and flagged instead of silently merged. identity_digest provides a filename suffix; it is not evidence that a retrieved file is correct.

PDF candidates retain url, source, license, version, kind, optional referer and access/version provenance. The canonical candidate_request_key in models.py identifies behavioral request context for candidate storage, enrichment and downloader attempts; different kinds or Referers at the same URL must not be discarded as already tried. Credentials never belong in this key or the manifest. Kinds are pdf, landing, pmc_listing, jats or fulltext_xml (compatibility). PMC listing requests are discovery only, not permission to retrieve any object.

A successful PDF requires parser-verified structure plus first-page article-title and DOI/author agreement, and a stored SHA-256. A DOI in references, a matching filename, a generic PDF signature, or a supplementary file is not enough. Explicit correction/retraction notices cannot stand in for the original article, and conflicting labeled arXiv base identifiers require review. identity_status is unverified, verified, manual_review or mismatch. Unclear files are preserved under review/ without counting as PDF success. Existing files are rechecked before reuse and before a pdf-only Zotero plan/import; checksum conflicts remain in extra.pdf_checksum_conflicts across retrieval phases and manifest roundtrips.

local_pdf, sha256, download_source, download_url, download_version and retrieval_type describe accepted PDFs. duplicate_of points to the already accepted PDF when bytes repeat. A local_fulltext plus fulltext_format describes a qualified JATS prose reader, not the original PDF. retrieval_type distinguishes original-version, accepted-manuscript, preprint, repository, JATS-generated, browser-OA and user-authorized institutional copies; an unknown version remains unknown.

## Record statuses

pending; downloaded; already_downloaded; fulltext_only; duplicate_pdf; deferred; manual_review; rejected_source; no_oa_version; rate_limited; anti_bot; dead_link; not_pdf; too_large; license_unknown; download_timeout; download_failed; landing_unresolved; fulltext_unavailable.

Legacy status strings remain readable. A failure means the attempted routes did not provide an accepted PDF, not proof that no lawful route exists. A fulltext_only record can have a PDF that failed elsewhere; it does not establish that no PDF object exists.

## Denominators

- record_count: every record in the frozen selected pool.
- attempted_records: records with an attempt or non-pending status; pending_records are not treated as failed downloads.
- pdf_count / pdf_downloaded / downloaded: locally present, identity-verified PDF records deduplicated by SHA-256.
- download_rate: unique verified PDFs / frozen selected pool.
- attempted_download_rate: unique verified PDFs / attempted records.
- task_completion_rate: unique verified PDFs / requested target, capped at 1; not a retrieval success rate.
- fulltext_only_count: locally present prose readers on records without an accepted PDF.
- readable_fulltext_count: unique PDFs plus those prose readers, reported separately.
- unverified_legacy_pdf_records: old claimed PDF successes not yet identity-verified; they do not inflate current verified metrics.

Source downloads_won are ordered winning routes, not measured marginal yield. Multi-query diagnostics sum run-record totals, not unique articles across queries. A download-rate comparison requires the same frozen candidate population and verification rule; changing the denominator or identity standard is not a measured gain.

article_type_counts and pdf_article_type_counts classify explicit provider metadata. research, review, case_report, letter, editorial, preprint and unknown are not SCIE indexing decisions. Report unknown metadata rather than treating it as original research.

## Zotero

The zotero field stores planned actions, match evidence, item/attachment keys, non-secret server_id and outcomes. Its presence is not proof of a completed import. parent_readback and attachment_readback distinguish pending from verified checks in the current import; older success records without them do not gain retrospective readback evidence. The partial statuses parent_created, parent_readback_failed, parent_created_attachment_unverified and parent_created_attachment_failed preserve durable keys. The planner maps them to resume_parent or resume_attachment without creating a replacement parent. Use the separate local-API reference for the authoritative verification and explicit preview/write workflow. Never store API keys, email credentials, cookies or authentication headers in run artifacts.
